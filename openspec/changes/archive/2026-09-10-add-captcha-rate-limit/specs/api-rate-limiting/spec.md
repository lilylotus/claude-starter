## ADDED Requirements

### Requirement: 声明式接口频率限制
系统 SHALL 提供一个可标注在 Controller 方法上的注解（如 `@RateLimit`），标注后该方法的调用
SHALL 受"时间窗口秒数内最多请求次数"规则约束。注解 SHALL 支持在方法上单独覆盖时间窗口秒数
与最大请求次数；未显式指定时 SHALL 使用全局默认配置（`application.yml` 中可配置，系统提供
合理默认值，如默认时间窗口 60 秒、默认最大请求次数 60 次）。限流状态 SHALL 基于 Redis 实现
（不使用进程内存状态），以支持多实例部署下限流状态共享一致。

#### Scenario: 使用方法级覆盖的限流参数
- **WHEN** 某接口方法上的注解显式指定"10 秒内最多 3 次"
- **THEN** 该接口在任意 10 秒滑动/固定窗口内第 4 次及以后的请求 SHALL 被限流拒绝，其余未标注
  该注解的接口不受影响

#### Scenario: 未覆盖参数时使用全局默认配置
- **WHEN** 某接口方法上标注了该注解但未指定时间窗口与最大请求次数
- **THEN** 系统按 `application.yml` 中配置的全局默认时间窗口与最大请求次数对该接口限流

#### Scenario: 多实例部署下限流状态共享
- **WHEN** 应用以多实例部署，同一 IP 在时间窗口内的请求被负载均衡分发到不同实例上处理
- **THEN** 各实例 SHALL 通过 Redis 共享同一份计数状态，跨实例的请求次数被合并计算，不因分发
  到不同实例而使限流失效

### Requirement: 按 IP 维度限流
系统 SHALL 以调用方 IP 地址作为限流的默认统计维度：同一 IP 对同一接口的请求次数在配置的时间
窗口内累计计数，不同 IP 之间的计数 SHALL 相互独立，不同接口（不同注解标注点）之间的计数
SHALL 相互独立。

#### Scenario: 不同 IP 互不影响
- **WHEN** IP A 在时间窗口内已达到某接口的最大请求次数，IP B 首次请求同一接口
- **THEN** IP A 的后续请求被限流拒绝，IP B 的请求 SHALL 正常放行

#### Scenario: 不同接口互不影响
- **WHEN** 同一 IP 在时间窗口内已达到接口甲的最大请求次数
- **THEN** 该 IP 对标注了独立限流规则的接口乙的请求 SHALL 不受接口甲计数影响，按接口乙自身
  的计数独立判断

### Requirement: 触发限流时的响应
当某次请求触发限流时，系统 SHALL 拒绝执行该方法的业务逻辑，直接返回统一的失败响应（复用
`common/` 下的全局响应结构 `{ code, message, data }`，`code` 为非 0 值，`message` 提示请求
过于频繁），不 SHALL 抛出未被全局异常处理器捕获的未分类异常。

#### Scenario: 达到窗口内最大次数后的下一次请求被拒绝
- **WHEN** 同一 IP 对同一接口在当前时间窗口内的请求次数已达到配置的最大值，再发起一次请求
- **THEN** 系统不执行该接口的业务逻辑，返回 `{ code, message, data }` 形状的限流提示响应

#### Scenario: 时间窗口过期后计数重置
- **WHEN** 同一 IP 对同一接口触发限流后，等待超过配置的时间窗口时长
- **THEN** 该 IP 对该接口的计数被重置，下一次请求 SHALL 被正常放行（重新开始新一轮计数）
