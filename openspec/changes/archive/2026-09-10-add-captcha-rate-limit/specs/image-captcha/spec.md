## ADDED Requirements

### Requirement: 图形验证码生成
系统 SHALL 提供无需身份校验即可访问的接口 `GET /api/captcha/image`，随机生成一个图形验证码，
返回验证码 id 与图片内容（base64 编码的图片数据，供前端直接渲染为 `<img>` 的 `src`）。验证码
类型 SHALL 支持两种，由配置决定当前启用哪一种（不 SHALL 由调用方在请求参数中指定类型）：

- 字符模式：随机生成大小写字母与数字混合的字符串，字符个数 SHALL 可配置，默认 4 个。可选字符
  集合 SHALL 排除容易产生视觉歧义的字符，固定剔除数字 `0`、`1`，字母 `O`/`o`、`I`/`i`、`l`
  （大小写均剔除，不因大小写不同而保留其中一个）。
- 算式模式：随机生成一个简单的加、减、乘、除算式（两个操作数 + 一个运算符，如
  `"7 + 3 = ?"`），算式的正确计算结果作为答案；除法 SHALL 保证能整除（不产生小数结果）。

系统 SHALL 为本次生成的验证码分配一个唯一 id，将正确答案（连同验证码类型）以该 id 为 key
写入 Redis 并设置过期时间（默认 5 分钟，可配置），响应中 SHALL 只包含验证码 id 与图片，不
SHALL 包含明文答案。

#### Scenario: 字符模式下生成默认长度的验证码
- **WHEN** 配置的验证码类型为字符模式且未覆盖默认字符个数
- **THEN** 系统生成一个包含 4 个大小写字母/数字混合字符的验证码，返回验证码 id 与对应图片，
  同时将该 4 位字符串（不区分大小写）作为答案写入 Redis 并设置默认过期时间

#### Scenario: 字符个数可配置
- **WHEN** 配置的字符模式验证码长度被覆盖为 6
- **THEN** 系统生成的验证码图片中包含 6 个混合字符，Redis 中存储的答案长度同为 6

#### Scenario: 生成内容不包含易混淆字符
- **WHEN** 系统以字符模式生成任意一次验证码
- **THEN** 生成结果中不 SHALL 出现 `0`、`1`、`O`、`o`、`I`、`i`、`l` 中的任何一个字符

#### Scenario: 算式模式生成可整除的算式
- **WHEN** 配置的验证码类型为算式模式，且随机选中的运算符为除法
- **THEN** 系统 SHALL 只生成能整除的两个操作数组合，图片中展示的算式与 Redis 中存储的整数
  答案一致

### Requirement: 图形验证码一次性校验
系统 SHALL 提供供其他后端模块直接调用的校验能力（Java 方法形式，不要求必须暴露为独立 HTTP
接口），入参为验证码 id 与用户提交的答案，出参为校验是否通过的布尔结果。系统 SHALL 按以下
规则校验：

- 验证码 id 在 Redis 中不存在（未生成过、或已过期、或已被校验消费过）时，校验 SHALL 判定为
  失败。
- 字符模式下，比较 SHALL 不区分大小写；算式模式下，比较 SHALL 按数值精确匹配。
- 无论校验结果为成功还是失败，系统 SHALL 在本次校验完成后立即从 Redis 中删除该验证码 id
  对应的记录，使其不可被再次用于校验（一次性）。

#### Scenario: 答案正确且验证码未过期时校验通过
- **WHEN** 调用方提交的验证码 id 在 Redis 中存在未过期的记录，且提交的答案与存储答案匹配
  （字符模式不区分大小写／算式模式数值相等）
- **THEN** 校验返回通过，且该验证码 id 对应的 Redis 记录被立即删除

#### Scenario: 答案错误时校验不通过且验证码失效
- **WHEN** 调用方提交的验证码 id 在 Redis 中存在未过期的记录，但提交的答案与存储答案不匹配
- **THEN** 校验返回不通过，且该验证码 id 对应的 Redis 记录被立即删除

#### Scenario: 验证码不存在或已过期时校验不通过
- **WHEN** 调用方提交的验证码 id 在 Redis 中不存在（从未生成、已过期、或已被消费过）
- **THEN** 校验返回不通过，不 SHALL 抛出未分类异常

#### Scenario: 同一验证码 id 不可重复校验
- **WHEN** 调用方对同一个验证码 id 连续两次发起校验，第一次提交的答案正确
- **THEN** 第一次校验返回通过；第二次校验（无论提交什么答案）因该 id 已被消费而返回不通过
