## ADDED Requirements

### Requirement: 应用分页查询
系统 SHALL 提供分页查询应用列表的接口，不支持任何筛选参数；分页参数 `page`（默认 `1`）、`pageSize`（默认 `10`）均为可选；仅返回未被逻辑删除（`status != -1000`）的应用；每条记录包含应用名称、应用编码、负责人 id 及姓名、所属组织 id 及名称、显示序号、备注、状态；结果按 `showOrder` 降序、相同时按 `id` 升序排列。

#### Scenario: 查询应用分页列表
- **WHEN** 客户端调用 `GET /api/apps?page={page}&pageSize={pageSize}`
- **THEN** 系统返回未删除应用的分页结果，包含 `records`（含 `ownerName`、`orgName`）、`total`、`page`、`pageSize`，按 `showOrder` 降序排列

#### Scenario: 未指定分页参数时使用默认值
- **WHEN** 客户端调用 `GET /api/apps` 且未携带 `page`、`pageSize` 参数
- **THEN** 系统按 `page = 1`、`pageSize = 10` 处理

#### Scenario: 已逻辑删除的应用不出现在查询结果中
- **WHEN** 某个应用的 `status` 为 `-1000`
- **THEN** 该应用不出现在 `GET /api/apps` 的返回结果中

### Requirement: 应用详情查询
系统 SHALL 提供按 id 查询应用详情的接口，返回结果包含应用名称、应用编码、负责人 id 及姓名、所属组织 id 及名称、显示序号、备注、状态，以及创建人、创建时间、更新人、更新时间。

#### Scenario: 查询存在的应用
- **WHEN** 客户端调用 `GET /api/apps/{id}` 且该应用存在且未被逻辑删除
- **THEN** 系统返回该应用的完整信息

#### Scenario: 查询不存在的应用
- **WHEN** 客户端调用 `GET /api/apps/{id}` 且该 id 不存在或已被逻辑删除
- **THEN** 系统返回业务错误（非零 `code`），不返回 HTTP 500

### Requirement: 新增应用
系统 SHALL 支持创建应用，应用名称（`name`）、应用编码（`code`）、负责人 id（`ownerId`）、所属组织 id（`orgId`）为必填项；备注可选；显示序号默认 `0`。新建应用默认状态为启用（`2000`）。应用编码在未被逻辑删除的应用范围内须保持唯一。

#### Scenario: 成功创建应用
- **WHEN** 客户端调用 `POST /api/apps`，携带合法的 `name`、`code`、`ownerId`、`orgId`
- **THEN** 系统创建该应用，状态为 `2000`（启用），并返回创建后的应用信息

#### Scenario: 必填字段缺失时拒绝创建
- **WHEN** 客户端调用 `POST /api/apps` 且未携带 `name`、`code`、`ownerId` 或 `orgId` 之一
- **THEN** 系统拒绝创建，返回参数校验错误

#### Scenario: 应用编码已存在时拒绝创建
- **WHEN** 客户端调用 `POST /api/apps`，携带的 `code` 与某个未被逻辑删除的应用编码相同
- **THEN** 系统拒绝创建，返回业务错误（非零 `code`）

### Requirement: 更新应用
系统 SHALL 支持更新应用的名称、编码、负责人、所属组织、显示序号、备注；不通过本接口修改状态。更新时应用编码同样须在未被逻辑删除的应用范围内保持唯一（排除自身）。

#### Scenario: 成功更新应用
- **WHEN** 客户端调用 `PUT /api/apps/{id}`，携带合法的 `name`、`code`、`ownerId`、`orgId` 等字段
- **THEN** 系统更新该应用信息并返回更新后的结果，`status` 保持不变

#### Scenario: 更新时应用编码与自身相同不视为冲突
- **WHEN** 客户端调用 `PUT /api/apps/{id}`，携带的 `code` 与该应用自身当前编码相同
- **THEN** 系统正常更新，不因编码冲突而拒绝

#### Scenario: 更新时应用编码与其他应用冲突
- **WHEN** 客户端调用 `PUT /api/apps/{id}`，携带的 `code` 与另一个未被逻辑删除的应用编码相同
- **THEN** 系统拒绝更新，返回业务错误（非零 `code`）

### Requirement: 应用启用与停用
系统 SHALL 提供独立的接口将应用状态切换为启用（`2000`）或停用（`3000`），与新增/更新接口分离。

#### Scenario: 启用应用
- **WHEN** 客户端调用 `PUT /api/apps/{id}/enable`
- **THEN** 系统将该应用 `status` 置为 `2000` 并返回更新后的应用信息

#### Scenario: 停用应用
- **WHEN** 客户端调用 `PUT /api/apps/{id}/disable`
- **THEN** 系统将该应用 `status` 置为 `3000` 并返回更新后的应用信息

### Requirement: 应用逻辑删除
系统 SHALL 支持对应用执行逻辑删除（将 `status` 置为 `-1000`），不做物理删除。

#### Scenario: 成功删除应用
- **WHEN** 客户端调用 `DELETE /api/apps/{id}`
- **THEN** 系统将该应用 `status` 置为 `-1000`，该应用此后不再出现在分页查询、详情查询的结果中

### Requirement: 应用状态语义
系统 SHALL 使用统一的整型状态码表达应用的启停用与删除语义：`2000` 表示启用，`3000` 表示停用，`-1000` 表示已逻辑删除；三者互斥，与组织、用户、任职模块的状态码含义保持一致。

#### Scenario: 状态码含义一致
- **WHEN** 系统返回任意应用的 `status` 字段
- **THEN** 其值必为 `2000`、`3000`、`-1000` 三者之一，分别代表启用、停用、已删除

### Requirement: 应用管理前端界面
系统 SHALL 提供应用管理页面（路径 `/application/list`，菜单文案"应用管理"），以分页表格展示应用，顶部不提供搜索栏，按 `showOrder` 降序（相同时按 `id` 升序）分页展示（每页 10 条）。列表列包含应用名称、应用编码、负责人、所属组织、显示序号、状态、操作。页面 SHALL 支持新增、编辑、启用、停用、删除、详情：

- 新增/编辑：应用名称（必填输入框）、应用编码（必填输入框，须与其他未删除应用不重复）、负责人（必填，下拉远程搜索选择已存在用户，支持按姓名或手机号搜索）、所属组织（必填，组织树单选选择器）、显示序号（数字输入，默认 `0`）、备注（可选，多行文本）。
- 启用/停用/删除：与组织管理、用户管理、任职管理页面的交互模式一致（列表行内操作按钮 + 删除二次确认）。
- 详情：只读展示应用完整信息（应用名称、应用编码、负责人、所属组织、显示序号、备注、状态、创建人、创建时间、更新人、更新时间）。

#### Scenario: 应用列表按显示序号降序分页展示
- **WHEN** 用户打开应用管理页面
- **THEN** 系统调用 `GET /api/apps?page=1&pageSize=10`，按 `showOrder` 降序展示第一页应用，不携带任何筛选参数

#### Scenario: 翻页查看更多应用
- **WHEN** 用户在应用列表底部点击分页组件切换到其他页码
- **THEN** 系统按新页码重新查询并展示对应页的应用数据

#### Scenario: 新增应用时按姓名或手机号搜索负责人
- **WHEN** 用户点击"新增"打开弹窗，在负责人选择框中输入姓名或手机号关键字进行远程搜索并选中一个用户
- **THEN** 新增表单记录该用户为负责人（`ownerId`）

#### Scenario: 新增应用时选择所属组织
- **WHEN** 用户在新增/编辑弹窗的所属组织选择器中展开组织树并选中一个组织节点
- **THEN** 表单记录该组织为所属组织（`orgId`）

#### Scenario: 必填字段缺失时阻止提交
- **WHEN** 用户在新增/编辑弹窗中未填写应用名称、未填写应用编码、未选择负责人或未选择所属组织就点击"确定"
- **THEN** 表单校验失败，阻止提交，并在对应字段下提示必填

#### Scenario: 应用编码冲突时提交被拒绝
- **WHEN** 用户在新增/编辑弹窗中填写的应用编码与另一个未删除应用重复，并点击"确定"
- **THEN** 前端表单校验通过后提交请求，后端返回业务错误，页面提示"应用编码已存在"类错误信息，弹窗保持打开

#### Scenario: 列表操作触发的状态变更实时可见
- **WHEN** 用户在列表中对某一行执行启用、停用或删除操作
- **THEN** 操作成功后表格当前页数据刷新以反映最新状态；若刷新后当前页码超出新的总页数，则自动回退到最后一页

#### Scenario: 查看应用详情
- **WHEN** 用户在列表某一行点击"详情"
- **THEN** 系统以只读方式展示该应用的完整信息：应用名称、应用编码、负责人、所属组织、显示序号、备注、状态、创建人、创建时间、更新人、更新时间
