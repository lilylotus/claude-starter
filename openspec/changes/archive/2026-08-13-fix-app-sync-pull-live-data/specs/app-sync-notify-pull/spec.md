## MODIFIED Requirements

### Requirement: 按数据类型与 id 拉取变更数据
系统 SHALL 提供拉取接口，支持调用方传入数据类型与一个或多个被变更对象 id，返回这些 id 命中的变更记录（数据类型、操作类型、序列号、变更发生时间）与该对象当前在对应业务表（组织/用户/任职/应用/角色）中的真实数据；每个 id 只返回其在变更记录中的最新一条记录所对应的元信息，但 `data` 字段 SHALL 是现查业务表得到的当前状态，不是变更发生那一刻写入的历史快照。调用方只能拉取自身应用配置中该数据类型为"允许同步"的数据，请求了未开通数据类型时系统 SHALL 返回空结果而不是报错。若某条变更记录对应的业务对象在业务表中已经查不到（防御性场景，正常情况下不会发生），系统 SHALL 跳过该条记录，不在返回结果中包含它。

#### Scenario: 按 id 拉取到最新变更的当前数据
- **WHEN** 调用方使用某应用凭证请求数据类型"组织"、id 为某组织 id 的拉取接口，该组织此前有过新增和编辑两条变更记录，且业务表中该组织当前的字段值与编辑那次的变更快照不完全相同
- **THEN** 系统返回该组织在变更记录中最新一条（编辑）记录的元信息（序列号/操作类型/变更时间），但 `data` 字段是该组织当前在组织表中的真实字段值

#### Scenario: 请求未开通的数据类型返回空结果
- **WHEN** 调用方使用的应用凭证在角色数据域配置为"不允许同步"，请求数据类型"角色"的按 id 拉取接口
- **THEN** 系统返回空结果，不返回业务错误

### Requirement: 按序列号批量拉取变更数据
系统 SHALL 提供拉取接口，支持调用方传入一个起始序列号与批量大小，返回序列号大于起始值、按序列号升序排列、数量不超过批量大小的变更记录列表，供外部应用做增量同步；每条记录的 `data` 字段 SHALL 是该记录对应业务对象当前在对应业务表中的真实数据，不是变更发生那一刻写入的历史快照。调用方可选传入数据类型过滤，返回结果 SHALL 只包含调用方应用已开通同步的数据类型。若某条变更记录对应的业务对象在业务表中已经查不到（防御性场景），系统 SHALL 跳过该条记录。

#### Scenario: 按序列号增量拉取当前数据
- **WHEN** 调用方传入起始序列号 1000、批量大小 50
- **THEN** 系统返回序列号大于 1000、按升序排列、最多 50 条的变更记录，每条记录的 `data` 字段是对应业务对象当前在业务表中的真实数据

#### Scenario: 按数据类型过滤批量拉取
- **WHEN** 调用方传入起始序列号与数据类型"用户"
- **THEN** 系统返回的变更记录全部为数据类型"用户"的记录

#### Scenario: 必填参数缺失时返回明确的参数错误而非系统异常
- **WHEN** 调用方请求按序列号拉取接口时未携带必填参数 `fromSequence`，或携带的 `fromSequence` 不是合法数字
- **THEN** 系统返回业务错误（而不是笼统的系统内部错误），错误信息中明确指出是 `fromSequence` 参数缺失或格式不正确
