# admin-management Specification

## Purpose
管理员身份主数据的维护能力：把已存在的用户（`tab_user`）授予"管理员"身份，并关联其
拥有的角色（`tab_role`）与可管辖的组织范围（`tab_org`，含是否递归子组织）。提供管理员
的分页查询、详情查询、新增、编辑（角色/组织管辖范围随主表整体同步）、启用/停用、
逻辑删除接口，以及配套的管理员管理前端页面；是身份管理体系（组织 → 用户 → 角色 →
权限）中"用户被授予管理员身份、拥有哪些角色、能管辖哪些组织范围"这一层的基础能力，
为后续鉴权/数据权限收窄（按管辖组织范围过滤数据）打基础。
## Requirements
### Requirement: 管理员分页查询
系统 SHALL 提供分页查询管理员列表的接口，不支持任何筛选参数；分页参数 `page`（默认 `1`）、`pageSize`（默认 `10`）均为可选；仅返回未被逻辑删除（`status != -1000`）的管理员；每条记录包含管理员名称、管理员编码、关联用户 id 及姓名、显示序号、备注、状态，不包含角色列表与组织管辖范围列表；结果按 `showOrder` 降序、相同时按 `id` 升序排列。

#### Scenario: 分页查询管理员列表
- **WHEN** 客户端调用 `GET /api/admins?page=1&pageSize=10`
- **THEN** 系统返回按 `showOrder` 降序排列的第一页管理员数据，不携带任何筛选参数，每条记录含关联用户姓名但不含角色、组织管辖范围

### Requirement: 管理员详情查询
系统 SHALL 提供按 id 查询管理员详情的接口，返回结果包含管理员名称、管理员编码、关联用户 id 及姓名、显示序号、备注、状态、关联角色列表（角色 id 及名称）、管辖组织范围列表（组织 id、组织名称、是否包含递归子组织），以及创建人、创建时间、更新人、更新时间。

#### Scenario: 查询存在的管理员详情
- **WHEN** 客户端调用 `GET /api/admins/{id}` 且该管理员存在且未被逻辑删除
- **THEN** 系统返回该管理员的完整信息，包含其全部关联角色与全部管辖组织范围

#### Scenario: 查询不存在的管理员
- **WHEN** 客户端调用 `GET /api/admins/{id}` 且该 id 不存在或已被逻辑删除
- **THEN** 系统返回业务错误（非零 `code`），不返回 HTTP 500

### Requirement: 新增管理员
系统 SHALL 支持创建管理员，管理员名称（`name`）、管理员编码（`code`）、关联用户 id（`userId`）为必填项；显示序号默认 `0`；备注可选；可同时提交角色 id 列表（`roleIds`，可为空数组）与管辖组织范围列表（`orgScopes`，可为空数组，每项包含 `orgId`、`includeChildren`）。新建管理员默认状态为启用（`2000`）。管理员编码在未被逻辑删除的管理员范围内须保持唯一；关联用户 id 在未被逻辑删除的管理员范围内须保持唯一（同一用户不能同时关联两个未删除的管理员身份）。

#### Scenario: 成功创建管理员
- **WHEN** 客户端调用 `POST /api/admins`，携带合法的 `name`、`code`、`userId`，以及若干 `roleIds`、`orgScopes`
- **THEN** 系统创建该管理员，状态为启用，其角色关联与组织管辖范围与提交内容一致

#### Scenario: 必填字段缺失时拒绝创建
- **WHEN** 客户端调用 `POST /api/admins` 且未携带 `name`、`code`、`userId` 之一
- **THEN** 系统返回校验错误，不创建记录

#### Scenario: 管理员编码已存在时拒绝创建
- **WHEN** 客户端调用 `POST /api/admins`，携带的 `code` 与某个未被逻辑删除的管理员编码相同
- **THEN** 系统返回业务错误，不创建记录

#### Scenario: 用户已关联其他管理员时拒绝创建
- **WHEN** 客户端调用 `POST /api/admins`，携带的 `userId` 已被某个未被逻辑删除的管理员关联
- **THEN** 系统返回业务错误，不创建记录

### Requirement: 更新管理员
系统 SHALL 支持更新管理员的名称、编码、关联用户、显示序号、备注、角色列表、管辖组织范围；不通过本接口修改状态。更新时管理员编码、关联用户 id 同样须在未被逻辑删除的管理员范围内保持唯一（排除自身）。角色列表与管辖组织范围按整体替换语义处理：更新后的关联集合与本次请求携带的集合完全一致。

#### Scenario: 成功更新管理员基础信息与关联关系
- **WHEN** 客户端调用 `PUT /api/admins/{id}`，携带合法的 `name`、`code`、`userId`、新的 `roleIds`、新的 `orgScopes`
- **THEN** 系统更新该管理员的基础信息，其角色关联、组织管辖范围替换为本次请求携带的集合，不保留请求中未出现的旧关联

#### Scenario: 更新时编码与自身相同不视为冲突
- **WHEN** 客户端调用 `PUT /api/admins/{id}`，携带的 `code` 与该管理员自身当前编码相同
- **THEN** 系统正常更新，不因唯一性冲突拒绝

### Requirement: 管理员启用与停用
系统 SHALL 提供管理员启用、停用接口，仅修改状态字段，不影响管理员的角色关联与组织管辖范围。

#### Scenario: 启用管理员
- **WHEN** 客户端调用 `PUT /api/admins/{id}/enable`
- **THEN** 该管理员状态变为启用（`2000`）

#### Scenario: 停用管理员
- **WHEN** 客户端调用 `PUT /api/admins/{id}/disable`
- **THEN** 该管理员状态变为停用（`3000`）

### Requirement: 管理员逻辑删除
系统 SHALL 提供管理员逻辑删除接口，仅将状态置为已删除（`-1000`），不物理删除该管理员及其角色关联、组织管辖范围数据。

#### Scenario: 删除管理员
- **WHEN** 客户端调用 `DELETE /api/admins/{id}`
- **THEN** 该管理员状态变为已删除（`-1000`），后续分页查询、详情查询均不再返回该管理员

### Requirement: 管理员管理前端界面
系统 SHALL 提供管理员管理页面（路径 `/permission/admins`，挂在"权限管理"侧边栏分组下），以分页表格展示管理员，顶部不提供搜索栏，按 `showOrder` 降序（相同时按 `id` 升序）分页展示（每页 10 条）。列表列包含管理员名称、管理员编码、关联用户、显示序号、状态、操作，不展示角色与管辖组织范围。页面 SHALL 支持新增、编辑、启用、停用、删除、详情：

- 新增/编辑：管理员名称（必填输入框）、管理员编码（必填输入框，须与其他未删除管理员不重复）、关联用户（必填，下拉远程搜索选择已存在用户，支持按姓名或手机号搜索）、管理员角色（多选下拉，数据源为角色选项接口，页面挂载时一次性加载）、管辖组织范围（动态多行子表单，每行含组织树单选选择器与"含子组织"复选框，支持新增/删除行）、显示序号（数字输入，默认 `0`）、备注（可选，多行文本）。新增/编辑弹窗打开时才请求全量组织树，页面进入时不预先请求。
- 详情：只读展示管理员完整信息（管理员名称、管理员编码、关联用户、角色列表、管辖组织范围列表、显示序号、备注、状态、创建人、创建时间、更新人、更新时间）。

#### Scenario: 管理员列表按显示序号降序分页展示
- **WHEN** 用户打开管理员管理页面
- **THEN** 系统调用 `GET /api/admins?page=1&pageSize=10`，按 `showOrder` 降序展示第一页管理员，不携带任何筛选参数

#### Scenario: 页面进入时不预先请求全量组织树
- **WHEN** 用户打开管理员管理页面，且不打开新增或编辑弹窗
- **THEN** 系统不请求全量组织树查询接口 `GET /api/orgs/tree`

#### Scenario: 新增管理员时选择关联用户、角色与管辖组织范围
- **WHEN** 用户点击"新增"打开弹窗，选择关联用户，勾选若干角色，添加若干管辖组织范围行并为每行设置是否含子组织
- **THEN** 表单记录对应的 `userId`、`roleIds`、`orgScopes`，点击"确定"后提交创建请求

#### Scenario: 必填字段缺失时阻止提交
- **WHEN** 用户在新增/编辑弹窗中未填写管理员名称、未填写管理员编码或未选择关联用户就点击"确定"
- **THEN** 表单校验失败，阻止提交，并在对应字段下提示必填

#### Scenario: 列表操作触发的状态变更实时可见
- **WHEN** 用户在列表中对某一行执行启用、停用或删除操作
- **THEN** 操作成功后表格当前页数据刷新以反映最新状态；若刷新后当前页码超出新的总页数，则自动回退到最后一页

#### Scenario: 查看管理员详情
- **WHEN** 用户在列表某一行点击"详情"
- **THEN** 系统以只读方式展示该管理员的完整信息，包含角色列表与管辖组织范围列表（组织名称 + 是否含子组织）

### Requirement: 管理员详情操作历史展示
系统 SHALL 在管理员详情弹窗中展示该管理员的操作历史列表：按操作发起时间降序排列，每页 5 条，支持分页；覆盖新增、编辑、启用、停用四类操作（不包含删除记录——管理员被逻辑删除后其详情弹窗本身不可访问，历史列表天然不会出现删除记录）；每条历史记录展示操作时间、操作类型、操作人；点击某条记录可查看该次操作的字段级变更详情（旧值→新值，含管理员主数据字段及角色/组织管辖范围的汇总变更）。详情弹窗每次关闭后再重新打开 SHALL 展示截至当前的最新操作历史，不复用上一次打开时加载的旧数据。

#### Scenario: 打开管理员详情弹窗时展示操作历史
- **WHEN** 用户打开某个管理员的详情弹窗
- **THEN** 系统调用 `GET /api/operation-logs?resourceType=admin&targetId={该管理员id}&page=1&pageSize=5`，按操作发起时间降序展示该管理员的操作历史

#### Scenario: 查看某条操作历史的字段变更详情
- **WHEN** 用户在管理员详情弹窗的操作历史列表中点击某条记录的"查看变更"
- **THEN** 系统以只读方式展示该次操作的字段级变更列表，每项包含字段名、旧值、新值

#### Scenario: 该管理员没有可查询到的操作历史时展示空状态
- **WHEN** 该管理员是通过数据库迁移预置（Flyway 种子数据）创建、从未经由本系统的新增/编辑/启用/停用接口产生过操作记录
- **THEN** 操作历史列表展示为空并提示"暂无操作记录"，不视为异常

#### Scenario: 关闭详情弹窗后编辑再重新打开时展示最新操作历史
- **WHEN** 用户打开某个管理员的详情弹窗查看历史后关闭，随后编辑保存该管理员，再次打开同一管理员的详情弹窗
- **THEN** 操作历史列表 SHALL 重新拉取并展示包含刚才那次编辑在内的最新记录，而不是停留在上一次打开时的旧列表
